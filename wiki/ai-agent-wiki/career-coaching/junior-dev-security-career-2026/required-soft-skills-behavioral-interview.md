# Required soft skills + behavioral interview topics

> **TL;DR**: 2026 behavioral rounds still test STAR but the *content* shifted toward AI-collaboration, async communication, and learning agility. Every answer needs a specific incident, a specific process change, and a *number* (commit count, time saved, error rate).

The 2026 behavioral round still tests STAR answers, but the *content* has shifted toward **AI-collaboration**, **async communication**, and **learning agility in a rapidly changing field**.

**Standard behavioral rounds (still asked):**

- **Conflict stories** — a disagreement with a teammate or manager, how resolved, what you'd do differently. Best answers describe a *specific* incident and the *specific* technical or process change that came from it. Generic "I compromised" answers fail.
- **Failure / mistake stories** — a thing you shipped that broke, what you learned, what process change prevented recurrence. Junior answers should not be "I was a junior then so it was OK"; the bar is the same as senior.
- **Ownership / "above and beyond" stories** — a thing you did that wasn't in your job description. The dev-harness-kit portfolio is the strongest version of this for 2026 juniors.
- **Learning agility** — most recent non-trivial thing you learned, what you used to learn it, how long it took. The AI-coding era makes this the *most* important behavioral signal: the rate at which you learn new tools is the rate at which you'll stay valuable.

**New behavioral topics for 2026 (asked more than in 2024):**

- **AI collaboration style** — "how do you use AI in your workflow, and how do you decide when not to?" Look for a clear answer that includes: when AI helps (boilerplate, refactors, tests), when it doesn't (novel architecture, ambiguous requirements, anything where correctness is critical), and a process for verifying AI output. The dev-harness-kit portfolio's `dev-kit:review` skill is the strongest version of this answer.
- **Async / remote work** — how you communicate when you can't tap someone's shoulder. Strong answers describe specific artifacts: written decision records, RFCs, design docs, recorded Looms. Weak answers say "I just Slack them."
- **Documentation discipline** — can you write a README a new teammate can use on day 1? Can you write a runbook for an on-call? The Claude Code plugin marketplace's `plugin.json` + `skills/` + `SKILL.md` convention is essentially a documentation portfolio in disguise.
- **Tooling / "what would you automate"** — what's a thing you do manually that you wish you didn't? What would you build? Strong answers describe an actual artifact (script, plugin, CLI) — see [[resume-portfolio-dev-harness-kit|Resume / portfolio positioning]].

**Anti-patterns in behavioral answers:**

- "I work too hard" — the laziest answer; the interviewer is checking whether you have any self-awareness.
- "I'm a perfectionist" — a cliché; the interview is checking whether you understand tradeoffs.
- "We disagreed but ultimately agreed" — the failure to articulate *how* is the failure.
- Vague impact statements ("improved efficiency", "saved time") — every behavioral answer should have a *number* (commit count, lines changed, time saved, error rate, etc.).
